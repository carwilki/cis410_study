Part 1 · Text access, NLP, the retrieval problem

Text access vs. text mining

Exam topic 1 · Lessons 1.2, 7.1, 7.2

Text access (text retrieval) helps a user get to the relevant text. It turns "Big Text Data" into "Small Relevant Data" (Lesson 1.2, slide 2). The output is still text, and a human reads it. It comes in two modes: pull (a search engine, where the user takes the initiative) and push (a recommender system, where the system takes the initiative).

Text mining (≈ text analytics) goes further. It turns text data into high-quality information or actionable knowledge (Lesson 7.1, slide 2). The output is knowledge, such as a summary of opinions, topics, word associations or a predicted value. "Mining" stresses the process; "analytics" stresses the result. The course uses the two terms interchangeably.

Memorize

Text mining = "Turn text data into high-quality information or actionable knowledge". High-quality information minimizes human effort (on consuming text data); actionable knowledge supplies knowledge for optimal decision making.

Text retrieval is an essential part of any text-mining system in two ways: (1) it can be a preprocessor for text mining (big text → small relevant text); (2) it is needed for knowledge provenance (going back to the original text to verify a pattern).

Exam trap

A recommender system is still text access (push mode), not text mining: it delivers documents and does not extract knowledge from them. And text mining does not replace retrieval; it relies on retrieval as a preprocessor and for provenance.

Pull mode vs push mode

Exam topic 2 · Lesson 1.2

Both modes connect a user with the right information. They differ in who takes the initiative.

Memorize

Typical systemSearch engineRecommender system

Why the split makes sense: a temporary need is hard for a system to predict, so the user has to ask. A stable need (a research interest, a hobby) can be learned once. After that, the system can watch new items and send the relevant ones.

Examples · Lesson 1.2
  • Pull: you are about to buy a product, so you search for reviews. Once you have bought it, you no longer need the reviews.
  • Push: a news filter monitors the news stream and sends you articles that match your stable interest.
  • Push inside search: an ad on a search results page. Here the system has good knowledge of your need from your query.

A sophisticated system combines both modes. Reading: Belkin & Croft 1992, "information filtering and information retrieval: two sides of the same coin?" Information filtering here means the push mode.

Exam trap

Push mode does not always mean a long-standing interest. The slide gives a second condition: the "system has good knowledge about a user's need". The ad on a search page is push mode even though the need is ad hoc.

Querying vs browsing (pull mode)

Exam topic 3 · Lesson 1.2

The pull mode has two complementary forms.

Memorize

Querying: the user enters a (keyword) query and the system returns relevant documents. It works well when the user knows what keywords to use.

Browsing: the user navigates to relevant information by following a path enabled by the structures on the documents (e.g., links). It is more useful when the user wants to explore, doesn't know what keywords to use, or can't conveniently enter a query (e.g., on a cellphone).

Lecturer's analogy · Lesson 1.2

Sightseeing in a city:

  • If you know the address of an attraction, you take a taxi straight there. That is querying with the right keywords.
  • If you don't know it, you walk around, or take a taxi to a nearby place and then walk. That is browsing, or starting with a rough query and then browsing.

The lecturer stresses that today we have good support for querying but weak support for browsing. Browsing well needs a "topical map" of the information space, and building one is an open research question.

Exam trap

Querying and browsing are both pull mode, because the user acts in both. Do not call browsing "push".

What NLP can and can't do

Exam topic 4 · Lesson 1.1

Big picture: shallow NLP (POS tagging, partial parsing) works at large scale with reasonable accuracy. Deep NLP (full semantic analysis, even complete parsing) is hard. It works only in limited domains or on special tasks such as entity recognition.

Why deep NLP is hard: natural language is designed to make human communication efficient. So:

  • we omit a lot of "common sense" knowledge, which we assume the hearer has
  • we keep many ambiguities, which we assume the hearer can resolve

A computer would need knowledge representation and inference to fill these gaps. Both remain fundamental challenges in AI. The slide says: "Ambiguity is a 'killer'!" Modern NLP sidesteps the problem with supervised machine learning on large amounts of labeled training data.

What we can't do · Lesson 1.1, slide 8
  • 100% POS tagging: "He turned off the highway." vs "He turned off the fan." The word "off" has a different role in each.
  • General complete parsing: "A man saw a boy with a telescope."
  • Precise deep semantic analysis: what exactly does "own" mean in "John owns a restaurant."?

Consequence for text retrieval: a search engine must handle any kind of text, robustly and fast, so it can use only shallow NLP. The bag of words representation keeps the words and their counts but drops word order. It is sufficient for most search tasks (but not all!).

Some retrieval techniques also solve NLP problems on the side:

  • In the query "Java applet", the word "applet" selects the programming sense of "Java", which is word sense disambiguation.
  • Feedback adds related words to the query, which gives some semantic matching.
Exam trap

"Bag of words is enough for all search tasks" is false. The slide says "most search tasks (but not all!)", and deeper NLP is needed for complex search tasks.

POS tagging, parsing, and ambiguity

Exam topic 5 · Lesson 1.1

Memorize

POS tagging (lexical analysis): assign a syntactic category (noun, verb, …) to each word.

Parsing (syntactic analysis): determine the structure of a sentence, i.e., which words group into a noun phrase and which word modifies which.

Syntactic/structural ambiguity: the same sentence or phrase has more than one possible structure.

Worked example · Lesson 1.1, slide 4

"A dog is chasing a boy on the playground"

  1. Lexical (POS): Det Noun Aux Verb Det Noun Prep Det Noun
  2. Syntactic (parsing): Noun Phrase, Complex Verb, Noun Phrase, Prep Phrase → Verb Phrase → Sentence
  3. Semantic: Dog(d1). Boy(b1). Playground(p1). Chasing(d1,b1,p1).
  4. Inference: Scared(x) if Chasing(_,x,_). Applying the rule gives Scared(b1).
  5. Pragmatic (speech act): the speaker may be reminding someone to get the dog back.

Text retrieval vs database retrieval

Exam topic 8 · Lesson 1.3

What they share: a collection of items, a query that describes a need, and criteria for choosing results.

The key difference: a database has a schema, so an SQL query defines its answer set exactly, and the challenge is only to find that set fast. In TR the data is free text and the query is a fuzzy keyword query, so the query does not define the answer. The first challenge in TR is deciding which documents should be in the answer set, i.e., accuracy. Speed comes after.

Memorize · Lesson 1.3, slide 5
Text retrievalDatabase retrieval
InformationUnstructured/free text; ambiguous semanticsStructured data; well-defined semantics
QueryAmbiguous; incomplete specificationWell-defined semantics; complete specification
AnswersRelevant documentsMatched records

TR is an empirically defined problem: you can't mathematically prove one method is better than another. You must rely on empirical evaluation involving users.

The exam-topics list adds a point: because most online data mixes text fields with some structure, the two fields are moving closer. They share questions such as the right query language, accurate ranking, fast answers, and interactive search.

Exam trap

"TR is empirically defined" does not mean TR has no formal model. The slides give a formal formulation ($R(q)$, $R'(q)$). It means that which method is better must be judged with users, not proved.

Document ranking vs document selection

Exam topic 9 · Lesson 1.3

Memorize · formal setup (Lesson 1.3, slides 6–7)

Collection $C= \{d_1, \dots, d_M\}$. Set of relevant documents $R(q) \subseteq C$. $R(q)$ is generally unknown and user-dependent; the query is only a "hint". Task: compute $R'(q)$, an approximation of $R(q)$.

Strategy 1: Document selection. $$R'(q)=\{d\in C \mid f(d,q)=1\}$$ Here $f(d,q) \in\{0,1\}$ is an indicator function, or binary classifier. The system must decide if a doc is relevant or not: absolute relevance.

Strategy 2: Document ranking. $$R'(q) = \{d\in C \mid f(d,q)>\theta\}$$ Here $f(d,q) \in\Re$ is a relevance measure function, and $\theta$ is a cutoff determined by the user. The system only needs to decide if one doc is more likely relevant than another: relative relevance.

Why ranking is preferred:

  1. A selection classifier is unlikely to be accurate.
    • An "over-constrained" query returns no relevant documents.
    • An "under-constrained" query causes over-delivery.
    • Users rarely know the vocabulary of the relevant docs, so the right point between these extremes is hard to find.
    Ranking lets the user choose the cutoff, which is a natural form of "supervision" from the user.
  2. Even an accurate selection is not enough: relevance is a matter of degree, so the results still need prioritizing.

Memorize · Probability Ranking Principle [Robertson 77]

Ranking documents in descending order of probability of relevance is optimal under two assumptions:

  1. The utility of a document (to a user) is independent of the utility of any other document.
  2. A user would browse the results sequentially.
Exam trap · "Do these two assumptions hold?"

No, neither holds strictly.

  • Independence fails for near-duplicates: a second copy is useless once you have seen the first. It also fails for collective relevance: three docs together answer the question when none does alone.
  • Users don't always read sequentially: they skip results or look at the bottom.

The PRP is still the foundation for ranking.

Part 2 · Vector space model and system implementation

Stemming and stop words

Exam topic 10 · Lessons 2.4, 2.3, 2.1

Memorize

Stemming: mapping all inflectional forms of words to the same root form (Lesson 2.4, slide 4). Example: computer → compute, computation → compute, computing → compute.

Stop word: a word that usually doesn't reflect the content of the document it occurs in, e.g., the functional words of English ("the", "of", "about"). Words with very high document frequency can also be treated as stop words.

Why stem? Tokenization should map words with similar meanings to the same indexing term, so that a query word matches all its variants. This generally improves recall. It can hurt precision, because subtle differences such as computer vs computation sometimes matter. The lecturer: usually beneficial, but not always.

Why remove stop words? They are the highest-frequency words in Zipf's curve, so they are too common to discriminate between documents. They also have the longest postings lists, the "biggest data structure". Removing them shrinks the index a lot without hurting accuracy much.

Example · Lessons 1.6 / 2.1

For the query "news about presidential campaign", matching "about" says almost nothing about the topic, while matching "presidential" says a lot. "about" behaves like a stop word. IDF gives it the lowest weight in the lecture's example: $IDF(\text{about})=1.0$, the lowest of the five.

Other ways to define the dimensions are phrases, latent semantic indexing (word clusters) and character n-grams. In practice, bag-of-words with phrases is often sufficient (Lesson 2.3, slide 7). Some languages, such as Chinese, need word segmentation because there are no spaces between words.

Exam trap

Stemming generally raises recall; it does not mainly raise precision. Stop word removal mainly reduces index size, with little effect on accuracy.

Vector space model

Exam topic 12 · Lessons 1.5, 1.6, 2.1, 2.3

Idea: put each document and the query in the same high-dimensional space, with one dimension per term. Then rank documents by how close they are to the query. The core assumption is that a document more similar to the query is more relevant.

Memorize · VSM is a framework (Lesson 1.5, slide 5)

Query vector $\mathbf{q}=(x_1, \dots x_N)$, where $x_i\in\Re$ is the query term weight. Doc vector $\mathbf{d}=(y_1, \dots y_N)$, where $y_j\in\Re$ is the doc term weight. $N$ is the number of terms (the vocabulary size), so $N$ terms define an N-dimensional space.

$$\text{relevance}(q,d) \propto \text{similarity}(\mathbf{q},\mathbf{d}) = f(q,d)$$

Three things VSM doesn't say, which every instantiation must choose:

  1. How to define the dimensions (the "basic concept"). Concepts are assumed to be orthogonal.
  2. How to place docs and the query in the space, i.e., the term weights.
  3. How to define the similarity measure.
Memorize · Simplest VSM = Bit-Vector + Dot-Product + BOW (Lesson 1.6)

Each word $w_i$ in $V=(w_1,\dots,w_N)$ is a dimension. $x_i, y_i \in\{0,1\}$: 1 means word $W_i$ is present and 0 means absent.

$$Sim(q,d)=q.d= x_1y_1+\dots+x_Ny_N= \sum_{i=1}^{N} x_i y_i$$

Meaning: $f(q,d)$ = number of distinct query words matched in d.

TF, IDF, and document length normalization

Exam topic 13 · Lessons 1.4, 2.1, 2.2, 2.3

These are the three major term-weighting heuristics. Each one fixes a failure seen in the five-document example.

1. TF: reward repeated matches

Repeating "presidential" twice makes d4 more clearly about the query than d3. So use the count $c(w,d)$ instead of a 0/1 bit.

2. IDF: reward rare terms

Matching "presidential" should count more than matching "about", which occurs everywhere. So multiply by a weight that falls as more documents contain the word.

Memorize · IDF (Lesson 2.1, slide 9)
$$IDF(W) = \log\left[\frac{M+1}{k}\right]$$

Here $M$ = total number of docs in the collection, and $k$ = total number of docs containing $W$ (the doc frequency). The maximum is $\log(M+1)$, reached at $k=1$. The weight falls as $k$ grows.

Small example (log base 2 for easy numbers)

Take $M=7$, so $M+1=8$.

  • A word in $k=1$ doc gets $\log_2 8=3$.
  • A word in $k=2$ docs gets $\log_2 4=2$.
  • A word in $k=4$ docs gets $\log_2 2=1$.
  • A word in all $k=7$ docs gets $\log_2(8/7)\approx0.19$, close to zero.

The slides don't fix the log base. Changing the base rescales all IDF values by the same factor, so the ranking does not change.

The lecturer prefers the log curve to a linear penalty because it flattens out. Very common terms (e.g., in more than 50% of docs) all get similarly low weight, and the curve spends its distinctions on the rarer words.

3. Sublinear TF transformation: diminishing returns

Raw TF + IDF ranks d5 first: "campaign" appears 4 times, which gives 4×3.1 = 12.4. But the first occurrence tells the most; the 50th tells almost nothing. So bend the TF curve: transform $c(w,d)\rightarrow TF(w,d)$.

Memorize · TF-IDF ranking function (Lesson 2.2, slide 4)
$$f(q,d) = \sum_{i=1}^{N} x_i y_i = \sum_{w\in q\cap d} c(w,q)\,c(w,d)\log\frac{M+1}{df(w)}$$

$w\in q\cap d$: all matched query words in d. $c(w,q)$ and $c(w,d)$: the count of $w$ in the query and in the doc. $df(w)$: doc frequency (the same as $k$ above).

4. Document length normalization

A long document has a better chance of matching any query just by chance, so penalize it. But a document can be long for two reasons:

  • It uses more words for the same content (a full paper vs its abstract). Penalize this more.
  • It has more content (many abstracts concatenated). Penalize this less.

To avoid over-penalizing, use the average doc length as a pivot: the normalizer is 1 when $|d| = avdl$.

Memorize · Pivoted length normalizer (Lesson 2.3, slide 5)
$$normalizer = 1-b+b\frac{|d|}{avdl},\qquad b\in[0,1]$$

$|d|$: document length. $avdl$: average document length. $b$: degree of length normalization. When $b=0$ the normalizer is 1, which means no length normalization.

Read it as query TF × (double-log sublinear TF ÷ length normalizer) × IDF.

BM25 / Okapi

Exam topic 14 · Lessons 1.4, 2.2, 2.3

BM ("best matching") 25 is the most popular of the four equally strong models: pivoted normalization, BM25, query likelihood and PL2. Its TF part is a bounded, non-linear transformation of the count, with document length normalization built in.

Memorize · BM25 TF transformation (Lesson 2.2, slide 6)
$$y=\frac{(k+1)x}{x+k}$$

Here $x=c(w,d)$, $y=TF(w,d)$, and $k\ge0$.

  • Since $x/(x+k)<1$, $y$ can never reach $k+1$: the upper bound is $k+1$.
  • $k=0$ gives $y=1$ for every $x>0$, which is exactly the 0/1 bit vector.
  • A very large $k$ gives a nearly linear curve.

Why have an upper bound? It stops one term from dominating the score. A spammer can't win every query by repeating a word, and every matched query term still counts. The log transform has no upper bound.

Numeric example with $k=1$ (bound 2)
$x=c(w,d)$1234

Each extra occurrence adds less: the gains are 0.33, 0.17, 0.1.

Apply this to the lecture's d5 (campaign ×4) with the Lesson 2.1 IDF values. Its score falls from 13.9 to 1.5 + 1.6×3.1 = 6.46, below d3's 7.1. The over-counting problem is fixed. (This application is our extension; the slides stop at the formula.)

Memorize · BM25/Okapi [Robertson & Walker 94] (Lesson 2.3, slide 6)
$$f(q,d)=\sum_{w\in q\cap d} c(w,q)\,\frac{(k+1)\,c(w,d)}{c(w,d)+k\left(1-b+b\frac{|d|}{avdl}\right)}\,\log\frac{M+1}{df(w)}$$

Parameter ranges: $b\in[0,1]$ and $k_1, k_3\in[0,+\infty)$.

  • $k$ controls the TF ceiling, $k+1$.
  • $b$ controls how much document length matters. The pivoted normalizer multiplies $k$, so a longer doc gets a bigger denominator and a smaller term weight.
  • If $b=0$, there is no length normalization, and the TF part becomes the plain $\frac{(k+1)c(w,d)}{c(w,d)+k}$.
Numeric example: effect of b

Take $k=1$ and $c(w,d)=2$.

  • Average-length doc ($|d|/avdl=1$): the normalizer is 1 for any $b$, so TF = 4/3 ≈ 1.33.
  • Doc twice the average ($|d|/avdl=2$) with $b=0.5$: the normalizer is 1.5, so TF = 4/(2+1.5) ≈ 1.14 (penalized).
  • The same long doc with $b=0$: TF = 4/3 again (no penalty).

Extensions (Lesson 2.3, slide 8):

  • BM25F handles documents with fields ("F" = fields, e.g., title, body, anchor text). It first combines the term counts across all fields, then applies BM25 once. This avoids counting the valuable "first occurrence" again in every field.
  • BM25+ adds a small constant to TF to fix BM25's over-penalization of long documents. It is shown empirically and analytically to be better than BM25.

  • The exam-topics list says "k1 is the upper bound (i.e., the maximum value) of the TF formula". On the slides the bound is $k+1$, which is set by $k$. So if asked what $k_1$ controls, answer: the upper bound / saturation of TF. If asked for the exact maximum of $\frac{(k+1)x}{x+k}$, answer $k+1$.

Zipf's law

Exam topic 15 · Lessons 2.4, 2.5, 2.6

Memorize · Lesson 2.4, slide 9

rank × frequency ≈ constant

$$F(w)=\frac{C}{r(w)^{\alpha}},\qquad \alpha\approx 1,\ C\approx 0.1$$

$F(w)$: frequency of word $w$ (here a fraction of all word occurrences). $r(w)$: rank of $w$ when words are sorted by frequency. $C$: a constant. $\alpha$: a parameter adjusted to fit the data.

Numeric example ($\alpha=1$, $C=0.1$)

Rank 1 → 0.1, rank 2 → 0.05, rank 10 → 0.01, rank 100 → 0.001. In every case rank × frequency = 0.1.

Lesson 2.4, slide 8 gives the matching data: in news articles, the top 4 words make up 10~15% of word occurrences, and the top 50 words make up 35~40%.

Why it matters:

  • Stop words are the high-frequency head of the curve. Removing them saves the most index space.
  • Compression: most TF values are small, which favors short codes for small numbers.
  • Fast search: most terms are rare, so their postings lists are short. Scoring touches only a small fraction of the documents.
Exam trap

A low rank number (rank 1, 2, …) means high frequency. "Many words occur rarely" corresponds to high rank values. Also, the most frequent word in one corpus may be rare in another.

Inverted index: construction and score accumulators

Exam topic 16 · Lessons 2.4, 2.5, 2.6

Why an inverted index? Scanning every document for every query is too slow. Instead, precompute as much as possible: for each term, store the list of documents that contain it. A single-term query then becomes a lookup.

Memorize · Parts of the index
  • Term lexicon: term string ↔ integer term ID.
  • Doc ID lexicon: doc string (e.g., a URL) ↔ integer doc ID. Integers are easy to use as array indices and easy to compress.
  • Dictionary: modest size, needs fast random access, kept in memory if possible (hash table, B-tree, trie). It stores per-term statistics such as # docs (= df, for IDF) and total freq.
  • Postings: huge, read sequentially, can stay on disk. Each entry holds a docID, the term freq and, optionally, positions. Compression is desirable.

doc 1: "… news about". doc 2: "… news about organic food campaign…". doc 3: "… news of presidential campaign … … presidential candidate …"

Building a big index with little memory: sort-based inversion

Memorize · Lesson 2.5, slide 3
  1. Collect local (termID, docID, freq) tuples.
  2. Sort local tuples (to make "runs").
  3. Pair-wise merge runs.
  4. Output inverted file.

Memory-based methods are not usable for large collections.

Fast scoring with score accumulators

Memorize · general scoring form (Lesson 2.6, slide 3)
$$f(q,d) = f_a\big(h(g(t_1,d,q),\dots,g(t_k,d,q)),\ f_d(d),\ f_q(q)\big)$$
  • $g(t_i,d,q)$: the weight of a matched query term $t_i$ in $d$.
  • $h$: weight aggregation (e.g., a sum).
  • $f_a$: the final score adjustment, using a doc-level factor $f_d(d)$ (e.g., doc length) and a query-level factor $f_q(q)$.
  • $t_1,\dots,t_k$ are the query terms.

Algorithm (slide 4):

  1. $f_d(d)$ and $f_q(q)$ are pre-computed.
  2. Keep a score accumulator for each d, created only when needed.
  3. For each query term $t_i$, fetch the inverted list $\{(d_1,f_1),\dots,(d_n,f_n)\}$. For each entry $(d_j,f_j)$, compute $g(t_i,d_j,q)$ and add it to $d_j$'s accumulator.
  4. Finally, adjust each score with $f_a$ and sort.

  • Keeping only the most promising accumulators.
  • Parallel processing, for web scale.

If you keep only the most promising accumulators, process the rare term first. It matches few docs and has a high IDF, so the strongest candidates appear early and weak ones can be pruned.

Integer compression: unary, γ-code, δ-code, d-gap

Exam topic 17 · Lesson 2.5

Why compress? Postings lists are huge. A compressed index is smaller on disk, and it is also faster: reading from disk is slow compared with the CPU, so reading fewer bytes saves more time than decoding costs.

How it works: values are skewed, so use variable-length codes. Frequent small numbers get few bits; rare large numbers get more bits.

  • TF values: small numbers are far more frequent, because of Zipf.
  • Doc IDs are not skewed, so store the d-gaps $d_1, d_2-d_1, d_3-d_2,\dots$ instead. A frequent term has many docs, so its gaps are small. This works because postings are read sequentially.
Memorize · Lesson 2.5, slide 6 (log is base 2)

Binary: equal-length coding.

Unary: $x\ge1$ is coded as $x-1$ one bits followed by 0. For example, 3 ⇒ 110 and 5 ⇒ 11110.

γ-code: $x \Rightarrow$ unary code for $1+\lfloor \log x\rfloor$, followed by the uniform (binary) code for $x-2^{\lfloor \log x\rfloor}$ in $\lfloor \log x\rfloor$ bits. For example, 3 ⇒ 101 and 5 ⇒ 11001.

δ-code: the same as the γ-code, but the unary prefix is replaced with a γ-code. For example, 3 ⇒ 1001 and 5 ⇒ 10101.

Memorize · γ-decoding (Lesson 2.5, slide 7)
  1. Decode the unary part; let its value be $k+1$.
  2. Read $k$ more bits and decode them as binary; let the value be $r$.
  3. The encoded number is $2^k+r$.

d-gap decoding: decode $x_1$ to get doc ID1. Decode $x_2$ and add it to ID1. Repeat, each time adding the decoded value to the previous doc ID.

Decoding γ = 11010: the unary part 110 = 3 = $k+1$, so $k=2$. The next 2 bits, 10, give $r=2$. The number is $2^2+2=6$.

Exam trap
  • γ encodes $x$ itself, not $x-1$. The unary prefix encodes $1+\lfloor\log x\rfloor$, not $\lfloor\log x\rfloor$.
  • The binary part uses exactly $\lfloor\log x\rfloor$ bits, with leading zeros kept (9 → 001, not 1).
  • When decoding, the unary value is $k+1$, so you read $k$ bits, not $k+1$.
  • Unary for $x$ has $x-1$ ones, so 1 is just "0".

Slide note: here $k$ means $\lfloor\log x\rfloor$. That is unrelated to the $k$ in IDF or BM25.

Evaluation measures: precision, recall, F1, AP/MAP, gMAP, MRR, nDCG

Exam topic 18 · Lessons 3.1–3.6

Evaluation follows the Cranfield methodology. Build a reusable test collection: documents, queries, and relevance judgments. Then define measures that compare a system's results with the ideal results. The measures only need to be correlated with real user utility, because their job is to tell which method is better.

F-measure

Memorize · Lesson 3.2, slide 6
$$F_\beta=\frac{1}{\frac{\beta^2}{\beta^2+1}\frac{1}{R}+\frac{1}{\beta^2+1}\frac{1}{P}}=\frac{(\beta^2+1)P*R}{\beta^2P+R}\qquad F_1=\frac{2PR}{P+R}$$

Symbols: $P$ = precision, $R$ = recall, $\beta$ = parameter, often set to 1. It controls the emphasis on precision vs recall. $F_1$ is the harmonic mean of $P$ and $R$, i.e. $F_1=2/(1/P+1/R)$ (exam-topics PDF).

"Why not 0.5*P+0.5*R?" An arithmetic mean is dominated by the large value. A system can get perfect recall just by returning every document. Its precision is then near 0, but the average is still about 0.5. $F_1$ is high only when $P$ and $R$ are both reasonably high.

Small example

Return everything: $P\approx 0$, $R=1$. Arithmetic mean ≈ 0.5, while $F_1\approx 0$. With $P=0.5,R=1$: $F_1=\frac{2(0.5)(1)}{1.5}=2/3$, while the arithmetic mean is 0.75.

A ranked list gives one set per cutoff, because the user may stop anywhere. So compute precision and recall at every position where a new relevant doc appears, and plot precision against recall. For recall levels the list never reaches, assume precision = 0. This is pessimistic. It is fine for comparing methods as long as it is not biased toward any one method.

Memorize · Lesson 3.4, slide 3

Average Precision: the average of precision at every cutoff where a new relevant document is retrieved. Normalizer = the total # of relevant docs in collection.

MAP = arithmetic mean of average precision over a set of queries. gMAP = geometric mean of average precision over a set of queries.

$$\text{MAP}=\frac{1}{m}\sum_{j=1}^{m}AP_j\qquad \text{gMAP}=\Big(\prod_{j=1}^{m}AP_j\Big)^{1/m}$$

Symbols: $m$ = number of queries, $AP_j$ = average precision of query $j$. The slides give these two only in words; the formulas above restate the words.

Why AP is the standard measure:

  • It combines precision and recall. It averages precision values, and every missed relevant doc adds a 0.
  • It is sensitive to the rank of every relevant document. Move one relevant doc up and AP rises; move one down and AP falls.
  • Improving ranks near the top raises AP more than improving ranks near the bottom, because precision there has a smaller $k$ in its denominator. So AP has a built-in discount (exam-topics PDF).

Precision@10 does not have this sensitivity. Shuffle the 4 relevant docs anywhere in the top 10 and P@10 stays 4/10. That is why P@10 is meaningful to users but weak for comparing algorithms.

MAP or gMAP? The two can rank systems differently.

  • MAP, like any arithmetic mean, is dominated by large values, i.e. easy queries.
  • gMAP is affected more by low values, i.e. difficult queries. Use gMAP if you care most about improving hard queries.
Small example

Two queries with AP 0.1 and 0.9: MAP = 0.5, gMAP = $\sqrt{0.1\times0.9}=0.3$. The weak query lowers gMAP far more than it lowers MAP.

Mean Reciprocal Rank (Lesson 3.4, slide 4)

Memorize

When there is only one relevant document in the collection (e.g., known-item search, question answering):

$$\text{Average Precision}=\text{Reciprocal Rank}=1/r$$

Symbols: $r$ = the rank position of the single relevant doc. MAP over queries then becomes Mean Reciprocal Rank (MRR), the average of $1/r$.

"Why not simply use r?" For one query, $r$ and $1/r$ order systems the same way. Averaged over many queries, $r$ is dominated by large $r$, i.e. relevant docs ranked far down. Users care about the top. $1/r$ makes rank 1 vs 2 a big difference (1 vs 0.5) and rank 100 vs 1000 a tiny one.

Small example

Query 1: relevant doc at rank 1. Query 2: at rank 4. MRR = (1 + 1/4)/2 = 5/8. (Wrong method: average $r$ = 2.5, then 1/2.5 = 0.4.)

Multi-level judgments: nDCG (Lesson 3.5)

P, R and AP need binary judgments. With graded relevance (slide: r=1 non-relevant, 2 marginally relevant, 3 very relevant), the gain of a document is its level: the utility the user gets from reading it. nDCG is built in three steps:

  • Cumulative: add up the gains of the top $k$ docs.
  • Discounted: divide a lower-ranked doc's gain by a weight based on its rank, because the user may not reach it.
  • Normalized: divide by the DCG of the ideal ranking at the same cutoff.

Symbols: $g_i$ = gain (relevance level) of the doc at rank $i$; $k$ = cutoff.

Slide note: the log base is never stated. The divisor is $\log i$, not $\log(i+1)$. With base 2, $\log 2 = 1$, so rank 2 is effectively undiscounted too.

Why normalize?

  • Different queries have different maximum DCG. A query with nine highly relevant docs can reach a much larger DCG than a query with only two.
  • Without normalization, the average over queries would be dominated by those "easy", high-DCG queries.
  • Normalizing maps every query to [0, 1], where the ideal ranking scores 1, so each query contributes equally.
  • For a single query, normalization does not change which system wins, because IdealDCG is the same for all systems.
  • MAP needs no explicit normalization because AP is already in [0, 1]: it divides by the total number of relevant docs (exam-topics PDF question).

Pooling (slide 6)

Judging every document for every query is impossible on large collections. Which subset should we judge? Pooling:

  • Choose a diverse set of ranking methods, so the pool is broad.
  • Have each return its top-K documents.
  • Combine (union) all the top-K sets to form a pool for human assessors to judge.
  • Unjudged documents are usually assumed non-relevant (though they don't have to be).

This is fine for comparing systems that contributed to the pool. It is problematic for evaluating new systems. A new system may find relevant docs that were never judged, and those count as non-relevant, which is unfair to it.

Exam trap

Equal MAP differences can be reliable or unreliable. The two experiments have identical averages (0.20 vs 0.40), yet only Experiment 1 supports "B is better". The average alone does not tell you whether a difference is significant.

Part 4 · Language models and query likelihood

Statistical language model: unigram and bigram

Exam topic 6 · Lesson 4.2 · Bigram: exam-topics PDF, item 6

A statistical language model (LM) is a probability distribution over word sequences. It gives every sequence of words a probability, so two sequences can be compared. Why is this useful? Natural language is uncertain. An LM puts numbers on that uncertainty. For example, an ungrammatical sentence gets a much smaller probability than a grammatical one.

An LM is context-dependent. In everyday talk, "Today is Wednesday" is likely. In a math lecture, "The eigenvalue is positive" becomes more likely. An LM can also be seen as a machine that "generates" text, so it is called a generative model.

Worked example · Lesson 4.2, slide 4

"Today is Wednesday"≈ 0.001Grammatical, common
"Today Wednesday is"≈ 0.0000000000001Ungrammatical

Uses named in the lecture (slide 5):

  • Speech recognition: after "John feels", is "happy" or "habit" more likely?
  • Text categorization and retrieval: "baseball" three times and "game" once suggests sports.
  • Retrieval: how likely is a user interested in sports to type "baseball"?

Unigram LM

The simplest LM generates each word independently. The model is just a word distribution. Why make this assumption? Without it, we would need a probability for every possible combination of words. With it, we need only one probability per word.

Memorize
$$p(w_1 w_2 \ldots w_n)=p(w_1)p(w_2)\ldots p(w_n)$$ $$\text{Parameters: } \{p(w_i)\},\quad p(w_1)+\ldots+p(w_N)=1$$

Symbols: $w_1 \ldots w_n$ are the words of the text, in order. $p(w_i)$ is the probability of word $w_i$. $N$ is the vocabulary size. The $N$ probabilities must sum to 1, so strictly there are $N-1$ free parameters.

Worked example · Lesson 4.2, slide 6

p("today is Wed") = p("today") p("is") p("Wed") = 0.0002 × 0.001 × 0.000015.

Word order does not matter in a unigram LM. "Wed is today" gets exactly the same product.

Slide 7 shows two unigram LMs.

  • Topic 1, "Text mining": text 0.2, mining 0.1, association 0.01, clustering 0.02, …, food 0.00001.
  • Topic 2, "Health": food 0.25, nutrition 0.1, healthy 0.05, diet 0.02.

Sampling from Topic 1 tends to give a text-mining paper. A food-nutrition paper is still possible, just very unlikely.

Bigram LM (exam-topics PDF only)

The lectures never show a bigram LM. The exam-topics PDF (item 6) explains it.

The independence assumption "doesn't really hold in reality". After "web search", the word "engine" is much more likely: $p(w_3=\text{engine}\mid w_1=\text{web},w_2=\text{search})$ is much higher than $p(w_3=\text{engine})$. A bigram LM conditions each word on the word just before it, which captures local dependency between two adjacent words.

Memorize (exam-topics PDF, item 6)
$$p(D)=p(w_1)\,p(w_2\mid w_1)\,p(w_3\mid w_2)\ldots p(w_n\mid w_{n-1})$$

Symbols: $D=w_1 w_2 \ldots w_n$ is the document. $p(w_i\mid w_{i-1})$ is the probability of word $w_i$ given the previous word. Compare it with unigram: $p(D)=p(w_1)p(w_2)\ldots p(w_n)$.

Small example (made-up numbers)

Bigram: $p(\text{web})=0.5$, $p(\text{search}\mid\text{web})=0.4$, $p(\text{engine}\mid\text{search})=0.5$. Then p("web search engine") = 0.5 × 0.4 × 0.5 = 0.1.

Two more uses of an LM (slides 9–10):

  • Topic representation. Three levels of LM:
    • background LM $p(w\mid B)$, from general English
    • collection LM $p(w\mid C)$, from CS papers
    • document LM $p(w\mid d)$, from one text-mining paper
  • Word association. Divide the topic LM by the background LM: $p(w\mid\text{"computer"})/p(w\mid B)$. Common words score about 1. Related words score high: computer 400, software 150, program 104.
Exam trap

A unigram LM ignores word order. "Today is Wednesday" and "Today Wednesday is" get the same unigram probability. The slide's very different numbers come from a general LM that uses context, not from a unigram LM.

Maximum likelihood estimate of a unigram LM

Exam topic 7 · Lessons 4.2, 4.4

Given a document, how do we pick the word probabilities? The maximum likelihood (ML) estimator picks the setting of $p(w\mid\theta)$ that makes the observed document most probable. That means it maximizes $p(d\mid\theta)$, or equivalently $\log p(d\mid\theta)$. Any other setting would give the observed data a smaller probability. For a unigram LM, the answer is simply the word's relative frequency.

Memorize · Lesson 4.2, slide 8
$$p(w\mid\theta)=p(w\mid d)=\frac{c(w,d)}{|d|}$$

Symbols: $\theta$ is the unigram LM (the word distribution) being estimated. $c(w,d)$ is the count of word $w$ in document $d$. $|d|$ is the document length, the total number of words in $d$. Later lessons write the same thing as $p_{ML}(w\mid d)=\frac{c(w,d)}{|d|}$.

"Is this the best estimate?" ML is the best fit to this data. But the data is often a small sample, such as an abstract or a title, of a larger "population" (the full article). ML gives zero probability to every unseen word. Why? Any mass given to an unseen word is taken away from the observed words, and that lowers the likelihood of the observed data. So ML overfits a small sample. The fix is smoothing (topic 21).

Exam trap

The denominator is $|d|$, the total number of word tokens in $d$ (100 here). It is not the number of distinct words, and it is not the vocabulary size $N$.

Query likelihood retrieval and its smoothed rewriting

Exam topic 20 · Lessons 4.1, 4.3, 4.4, 4.5

Probabilistic models rank by $f(d,q)=p(R=1\mid d,q)$, where $R\in\{0,1\}$ is relevance. With click data this could be counted from a table, but unseen queries and documents break that. Query likelihood replaces it with:

Memorize · Lessons 4.1, 4.7
$$p(R=1\mid q,d)\approx p(q\mid d,R=1)\approx p(q\mid d)$$

Meaning: if a user likes document $d$, how likely would the user enter query $q$? The assumption is that a user formulates a query based on an "imaginary relevant document".

Worked example · Lesson 4.1, slide 4

Click table: $f(q,d)=p(R=1\mid d,q)=\frac{count(q,d,R=1)}{count(q,d)}$. From the table: P(R=1|q1,d1) = 1/2, P(R=1|q1,d2) = 2/2, P(R=1|q1,d3) = 0/2. This fails for unseen documents and unseen queries.

The basic formula

Memorize · Lesson 4.3, slide 9
$$q=w_1w_2\ldots w_n\qquad p(q\mid d)=p(w_1\mid d)\times\ldots\times p(w_n\mid d)$$ $$f(q,d)=\log p(q\mid d)=\sum_{i=1}^{n}\log p(w_i\mid d)=\sum_{w\in V}c(w,q)\log p(w\mid d)$$

Symbols: $w_1\ldots w_n$ are the query words, so $n$ is the query length. $p(w\mid d)$ is the document language model. $V$ is the vocabulary. $c(w,q)$ is the count of $w$ in the query, which is 0 for words not in the query.

Why each piece is there:

  • Product: each query word is assumed to be generated independently.
  • log: it avoids underflow from multiplying many small numbers, and it keeps the same document order.
  • So the retrieval problem becomes estimation of $p(w_i\mid d)$. Different estimation methods give different ranking functions.
Worked example · Lesson 4.3, slides 5–6

Here $p(w\mid d)=c(w,d)/|d|$ (ML) and $q$ = "presidential campaign".

  • d4 "… news of presidential campaign … presidential candidate …": $p(q\mid d4)=\frac{2}{|d4|}*\frac{1}{|d4|}$
  • d3 "… news of presidential campaign …": $p(q\mid d3)=\frac{1}{|d3|}*\frac{1}{|d3|}$
  • d2 "… news about organic food campaign…": $p(q\mid d2)=\frac{0}{|d2|}*\frac{1}{|d2|}=0$

Result: d4 > d3 > d2, as expected. For instance, with $|d4|=10$: $2/10 \times 1/10 = 0.02$.

Now try $q$ = "presidential campaign update". No document contains "update", so every score is 0 and d3 and d4 can't be told apart. The cause is the assumption that each query word is drawn from the document itself. The fix is to draw from a smoothed document model.

Smoothing with the collection LM, then rewriting

Memorize · Lesson 4.4, slide 5
$$p(w\mid d)=\begin{cases}p_{Seen}(w\mid d) & \text{if } w \text{ is seen in } d\\ \alpha_d\,p(w\mid C) & \text{otherwise}\end{cases}$$

Symbols:

  • $p_{Seen}(w\mid d)$ is the discounted ML estimate for words that occur in $d$.
  • $p(w\mid C)$ is the collection language model.
  • $\alpha_d$ is a coefficient that sets how much probability mass goes to unseen words. It is constrained so all probabilities sum to 1.

Idea: an unseen word's probability is proportional to its probability in a reference LM, here the collection.

Derivation · Lesson 4.4, slide 6

Split the sum into query words matched in $d$ and not matched:

$$\log p(q\mid d)=\sum_{w\in V,\,c(w,d)>0}c(w,q)\log p_{Seen}(w\mid d)+\sum_{w\in V,\,c(w,d)=0}c(w,q)\log\alpha_d\,p(w\mid C)$$

Write "not matched" as "all query words" minus "matched", then merge the two sums over matched words:

$$=\sum_{w\in V,\,c(w,d)>0}c(w,q)\log\frac{p_{Seen}(w\mid d)}{\alpha_d\,p(w\mid C)}+|q|\log\alpha_d+\sum_{w\in V}c(w,q)\log p(w\mid C)$$
Memorize · Lesson 4.6, slide 3 (rewritten ranking formula)
$$\log p(q\mid d)=\sum_{\substack{w_i\in d\\ w_i\in q}}c(w,q)[\log\frac{p_{Seen}(w_i\mid d)}{\alpha_d\,p(w_i\mid C)}]+n\log\alpha_d+\sum_{i=1}^{n}\log p(w_i\mid C)$$ $$f(q,d)=\sum_{\substack{w_i\in d\\ w_i\in q}}c(w,q)[\log\frac{p_{Seen}(w_i\mid d)}{\alpha_d\,p(w_i\mid C)}]+n\log\alpha_d$$

Symbols: $n=|q|$ is the query length. The sum runs over query words that also occur in $d$ (matched terms).

Slide note: the derivation slide writes $|q|\log\alpha_d$ and sums over $w\in V$. The "Benefit of Rewriting" slide (4.4/4.5) writes $n\log\alpha_d$ and omits $c(w,q)$. Lessons 4.6–4.7 include $c(w,q)$ and mix $w$ and $w_i$ in the indices. All of them mean the same thing.

Smoothing: Jelinek-Mercer and Dirichlet prior

Exam topic 21 · Lessons 4.4, 4.6, 4.7

Why smooth?

  • A document is a small sample of what the author could have written. Smoothing tries to recover the model of the whole article from its abstract.
  • ML gives every unseen word probability 0. One unmatched query word would then make $p(q\mid d)=0$.
  • Smoothing takes some mass from seen words and gives it to unseen words. This also makes the estimate more accurate in general.

Both methods start from the ML estimate $\frac{c(w,d)}{|d|}$ and mix in the collection LM $p(w\mid C)$ to avoid zeros. They differ only in how much smoothing each document gets.

Memorize · Jelinek-Mercer (Lesson 4.6, slide 4)
$$p(w\mid d)=(1-\lambda)\frac{c(w,d)}{|d|}+\lambda\,p(w\mid C)\qquad \lambda\in[0,1]$$

Symbols:

  • $\lambda$ is the smoothing parameter, the weight on the collection LM. Larger $\lambda$ means more smoothing.
  • $c(w,d)$ is the count of $w$ in $d$, and $|d|$ is the document length.
  • $p(w\mid C)$ is the collection LM.
  • Here $\alpha_d=\lambda$: a fixed coefficient, the same for every document.
Memorize · Dirichlet prior (Lesson 4.6, slide 5)
$$p(w\mid d)=\frac{c(w;d)+\mu\,p(w\mid C)}{|d|+\mu}=\frac{|d|}{|d|+\mu}\frac{c(w,d)}{|d|}+\frac{\mu}{|d|+\mu}p(w\mid C)\qquad \mu\in[0,+\infty)$$

Symbols: $\mu$ is the smoothing parameter (a non-negative number). Here $\alpha_d=\frac{\mu}{|d|+\mu}$, which depends on the document length.

How to remember it: add a pseudocount $\mu\,p(w\mid C)$ to every word, seen or unseen. In total that adds $\sum_w\mu\,p(w\mid C)=\mu$, which is why the denominator is $|d|+\mu$.

Slide note: the slide prints $c(w;d)$ with a semicolon, and its first denominator reads "d|+μ"; it means $|d|+\mu$.

Ranking functions (Lesson 4.7)

Plug each method into $f(q,d)=\sum c(w,q)[\log\frac{p_{Seen}(w_i\mid d)}{\alpha_d\,p(w_i\mid C)}]+n\log\alpha_d$:

Memorize · Lesson 4.7, slides 3–4
$$f_{JM}(q,d)=\sum_{\substack{w\in d\\ w\in q}}c(w,q)\log[1+\frac{1-\lambda}{\lambda}\frac{c(w,d)}{|d|\,p(w\mid C)}]$$ $$f_{DIR}(q,d)=[\sum_{\substack{w\in d\\ w\in q}}c(w,q)\log[1+\frac{c(w,d)}{\mu\,p(w\mid C)}]]+n\log\frac{\mu}{\mu+|d|}$$

$n$ is the query length. JM has no $n\log\alpha_d$ term, because $\alpha_d=\lambda$ is the same for all documents and is dropped.

  • JM: $|d|\,p(w\mid C)$ is the expected count of $w$ if $|d|$ words were drawn from the collection. The ratio compares the actual count $c(w,d)$ with that expected count.
    • TF: $c(w,d)$ in the numerator
    • IDF: $p(w\mid C)$ in the denominator
    • Length normalization: $|d|$ in the denominator
    It works like a VSM dot product.
  • Dirichlet: the ratio compares $c(w,d)$ with the expected count from $\mu$ sampled words. There is no $|d|$ inside the sum. Length normalization lives in $n\log\frac{\mu}{\mu+|d|}$, which is more negative for longer docs. It is no longer a single dot product.
Small example (friendly numbers)

  • Dirichlet with $\mu=10$: $(2+1)/20=0.15$, the same because $\mu=|d|$.
  • Unseen word with $p(w\mid C)=0.2$: both give $0.5\cdot0.2=0.1$.

Exam trap

Relevance, pseudo and implicit feedback

Exam topic 11 · Lessons 5.1, 5.2

Feedback means the system learns from judgments on its first results and then updates the query. The updated query is used to rank again. The three kinds of feedback differ only in where the judgments come from.

Slide wording: relevance feedback "judgments are reliable, but users don't want to make extra effort"; pseudo "judgments aren't reliable, but no user activity is required"; implicit "judgments aren't completely reliable, but no extra effort from users".

Why relevance feedback is not enough. User studies show people are often unwilling to make judgments. So the reliable signal is rarely available in practice.

Why pseudo feedback works at all. The top-ranked documents may not be relevant, but they look like relevant documents. Words that co-occur with the query words in those top documents are likely related to the query. The new terms expand the query and raise recall. Better term weights can also raise precision. Pseudo feedback helps on average but can hurt some queries, because the cutoff k is set arbitrarily.

Worked example · Lesson 5.1

Query = "computer". Take the top-n documents that match "computer". Count the words in that set. Compare with the background (collection) language model. Keep words that are frequent in the top set but not frequent in the whole collection, e.g. "program", "software". Add them to the query. Now documents that say "software" but never "computer" can also be found.

Implicit feedback details. Documents ranked above a clicked document can be assumed seen but skipped. The lecturer notes you can even learn from just the snippet the user saw, since the displayed text is what made the user click. Modern engines (Google, Bing) rely heavily on this.

Exam trap

Pseudo feedback does not involve the user at all. It can even run before results are shown. Implicit feedback does involve the user (their clicks are observed), but asks for no explicit judgments.

Exam trap

Reliability order: relevance (most) > implicit > pseudo (least). Do not put implicit at the bottom.

Rocchio feedback

Exam topic 22 · Lesson 5.2

In the vector space model, feedback means query modification: add new weighted terms (query expansion) and adjust the weights of old terms. Rocchio does this geometrically. If the relevant documents should rank on top, the best query sits at the centroid (average vector) of the relevant documents. So Rocchio moves the query vector toward the relevant centroid and away from the non-relevant centroid.

Memorize
$$\vec{q}_m = \alpha\,\vec{q} + \frac{\beta}{|D_r|}\sum_{\forall \vec{d}_j \in D_r} \vec{d}_j \;-\; \frac{\gamma}{|D_n|}\sum_{\forall \vec{d}_j \in D_n} \vec{d}_j$$

Symbols: $\vec{q}_m$ = new query; $\vec{q}$ = original query; $D_r$ = set of relevant docs, $|D_r|$ its size; $D_n$ = set of non-relevant docs, $|D_n|$ its size; $\vec{d}_j$ = a document vector. $\frac{1}{|D_r|}\sum \vec{d}_j$ is just the centroid of the relevant docs (same for $D_n$). $\alpha, \beta, \gamma$ = parameters: weight on the original query, on the positive centroid, and on the negative centroid. They are set empirically.

Easy recall: new query = α·(old query) + β·(relevant centroid) − γ·(non-relevant centroid).

Rocchio in practice (slide 7), with the reasons:

  • Negative examples are not very important. Why: non-relevant docs are scattered in all directions, so their centroid points nowhere useful. Relevant docs cluster together and point one consistent way. So γ is often small or 0. Exception: for hard queries where most results are negative, negative feedback helps.
  • Truncate the vector. Keep only the few highest-weight terms of the centroid. Why: after expansion many terms become non-zero, and scoring cost grows with the number of query terms (efficiency).
  • Avoid over-fitting: keep a relatively high weight on the original query. Why: the feedback sample is small, and the user chose the original terms as the most important. A low α causes topic drift. This matters most for pseudo feedback.
  • β larger for relevance feedback than for pseudo feedback. Why: explicit judgments are reliable; assumed-relevant top docs are not.
  • Usually robust and effective. BM25 + Rocchio pseudo feedback is regarded as state of the art for bag-of-words retrieval without real feedback data (exam topics PDF).
Exam trap

Divide each sum by the number of docs in that set ($|D_r|$ or $|D_n|$). Summing without averaging gives the wrong centroid. Also, the − sign is on the γ term only.

Exam trap

The slide says β (not α) should be larger for relevance feedback than for pseudo feedback.

(3) Dynamics: pages are created and updated constantly, so the index must stay fresh. Opportunity: extra signals such as links and layout.

Memorize

Crawler (spider, robot): a program that fetches Web pages. Toy crawler: start with seed pages in a priority queue → fetch pages → parse them for hyperlinks and add those to the queue → follow the links in the queue.

Real crawler issues: robustness (server failure, traps of dynamically generated pages), crawling courtesy (server load, robot exclusion), file types (images, PDF), URL extensions (cgi scripts, internal references), redundant/duplicate pages, "hidden" URLs (found by truncating a long URL).

Crawling strategies. Breadth-first is common because it balances server load: the crawler does not hammer one server. Parallel crawling is natural. Focused crawling targets one topic (e.g., all pages about "automobiles"), typically starting from a query. Incremental (repeated) crawling re-visits only what is worth it, to minimize resources. Learn from history: target (1) frequently updated pages (a sports score page) and (2) frequently accessed pages (high utility to users). A static page unchanged for months need not be re-crawled daily. New pages that no old page links to are hard to find.

Exam PDF wording: exploratory crawling (follow links, collect as many pages as possible) vs updating crawling (revisit crawled pages to stay fresh). Slide wording: initial crawling (complete vs focused) vs incremental crawling.

Handling the size of the Web (Lesson 5.5). The index cannot fit on one machine, and building it on one machine is too slow. Google's answers:

  • Google File System (GFS): distributed file system. Fixed chunk size 64 MB; each chunk is replicated for reliability; simple centralized management (a master keeps the namespace and chunk locations); data transfer goes directly between the application and chunk servers, not through the master.
  • MapReduce: framework for parallel computation (topic 25). Hadoop = open-source MapReduce. (The exam PDF also lists Big Table, a column-based database.)
  • Result: many machines store the inverted index and many machines answer queries in parallel.
Memorize

Anchor text = the text describing a hyperlink. It reflects how people describe the target page, so it resembles the query a user would type to find that page. A query matching anchor text is good evidence that the page pointed to is relevant, even if that page itself does not contain the query words.

Worked example · Lesson 5.6

Someone links to Amazon's front page with the text "the biggest online bookstore". The query "online bookstore" matches this anchor text, which gives evidence for Amazon's page (the target), not the page that holds the link.

Exam trap

PageRank

Exam topic 24 · Lessons 5.6, 5.7

Why it helps Web search. Links are like citations. A page cited often is likely more useful. PageRank is "citation counting" (inlink counting) improved in two ways: (1) indirect citations count: being linked from a page that itself has many inlinks counts more; (2) smoothing of citations: every page gets a non-zero pseudo citation count. It scores a page's popularity / authority, independent of the query.

Memorize · random surfing model (slide 6)

At any page: with prob. $\alpha$, randomly jump to another page; with prob. $(1-\alpha)$, randomly pick a link to follow. $p(d_i)$, the PageRank score of $d_i$, is the average probability of visiting page $d_i$.

Convention warning: in these slides $\alpha$ is the random-jump probability, and the lecture example uses $\alpha = 0.2$. Many other sources say "damping factor 0.85" and mean the probability of following a link. That is the opposite meaning: 0.85 there corresponds to $1-\alpha = 0.8$ here. Use the slide meaning on the exam.

Memorize · formulas
$$p_{t+1}(d_j) = (1-\alpha)\sum_{i=1}^{N} M_{ij}\, p_t(d_i) + \alpha \sum_{i=1}^{N} \tfrac{1}{N}\, p_t(d_i)$$

Symbols: $N$ = number of pages; $M_{ij}$ = probability of going from $d_i$ to $d_j$ (transition matrix; each row sums to 1: $\sum_{j=1}^{N} M_{ij} = 1$); $p_t(d_i)$ = probability of being at page $d_i$ at time $t$. First term: reach $d_j$ by following a link. Second term: reach $d_j$ by random jumping.

Drop the time index (equilibrium):

$$p(d_j) = \sum_{i=1}^{N}\left[\tfrac{1}{N}\alpha + (1-\alpha)M_{ij}\right] p(d_i) \qquad \vec{p} = (\alpha I + (1-\alpha)M)^T\, \vec{p}, \quad I_{ij} = 1/N$$

Here $I$ is not the identity matrix. Every entry of $I$ is $1/N$ (the uniform "jump anywhere" matrix).

Why the jump term? Think of $\alpha I + (1-\alpha)M$ as a smoothed transition matrix: real links plus a virtual link between every pair of pages. It has no zero entries, so the surfer never gets stuck and the iteration is guaranteed to converge. The equation has $N$ unknowns and $N$ linear equations; it is an eigenvector equation, solved by iterating.

How to compute (power iteration): set initial $p(d) = 1/N$; repeat $\vec{p} \leftarrow A^T\vec{p}$ with $A = \alpha I + (1-\alpha)M$; stop when the values converge. Each step can be read as propagating scores along the links: a page collects the scores of the pages that point to it.

MapReduce

Exam topic 25 · Lesson 5.5

MapReduce is Google's general framework for parallel programming, built on GFS. Why it exists: let a programmer run a job on a large cluster with minimal effort. The framework hides low-level details (network, storage, where tasks run), has built-in fault tolerance (if a server dies, its unfinished task is re-dispatched to another server), and does automatic load balancing. The programmer writes only two functions: Map and Reduce.

Memorize · the pipeline

1. Input is split into (key, value) pairs. 2. Each pair goes to a Map(K,V), which outputs a set of new (key, value) pairs; the output key is usually different from the input key. 3. The framework collects and sorts all Map outputs so all values with the same key are grouped (shuffle and sort). 4. Each key with its list of values goes to a Reduce(K, V[ ]), which outputs the final (key, value) pairs. Different keys are reduced in parallel.

Worked example · Lesson 5.5, slides 8–10 (word count)

Input lines: 1 "Hello World Bye World", 2 "Hello Hadoop Bye Hadoop", 3 "Bye Hadoop Hello Hadoop". Map key = line number, value = the line's text.

Map(K, V) {
  For each word w in V, Collect(w, 1);
}
Reduce(K, V[ ]) {
  Int count = 0;
  For each v in V, count += v;
  Collect(K, count);
}

After grouping: <Bye → 1,1,1>, <Hadoop → 1,1,1,1>, <Hello → 1,1,1>, <World → 1,1>. Reduce output: <Bye, 3>, <Hadoop, 4>, <Hello, 3>, <World, 2>. Why parallel works: each line is counted independently, and counts for one word can be summed independently of other words.

Worked example · Lesson 5.5, slides 11–12 (inverted index)

Map key = docID, value = the document's text. Map counts each term in the doc and emits (term, (docID, count)). The docID must travel with the count, because the index needs it. The built-in shuffle groups by term. Reduce only appends and sorts the postings.

Content-based filtering with retrieval techniques

Exam topic 27 · Lessons 6.5, 6.6

Basic question: will user U like item X? Content-based filtering answers it by item similarity: look at what items U likes and check whether X is similar. (Collaborative filtering uses user similarity instead; topic 28.)

Extending a search engine into a filter (slide 6.5-8): (1) reuse retrieval scoring: treat the user profile as the query and score each arriving doc against it; (2) add a score threshold: deliver the doc only if its score is above the threshold; (3) improve the profile vector with traditional feedback (e.g., Rocchio) from the user's views and skips; (4) learn the threshold over time (new component).

Three basic problems: filtering decision (binary classifier: doc text, profile text → yes/no); initialization (from profile text or very few examples); learning from limited relevance judgments (only on delivered "yes" docs) and accumulated docs. All aim to maximize utility.

Memorize · linear utility (slide 6.5-6)
$$\text{Linear Utility} = 3 * \#good - 2 * \#bad$$

Symbols: #good (#bad) = number of good (bad) documents delivered to the user. Why a utility: a filter must decide in real time, so ranking measures such as MAP do not fit; utility scores the yes/no decisions directly.

Worked example · Lesson 6.5 quiz question

Deliver 5 good and 3 bad docs: $3\times5 - 2\times3 = 9$. "Are the coefficients (3, −2) reasonable? What about (10, −1) or (1, −10)?"

CoefficientsSame 5 good, 3 badBehavior it encourages
(10, −1)$50-3=47$Big reward, small penalty → deliver more (favors recall)
(1, −10)$5-30=-25$Small reward, big penalty → conservative, deliver only sure docs (favors precision)

The right coefficients depend on the application.

Why threshold learning is hard (slide 6.6-10): censored data: judgments exist only for delivered docs (the training sample is biased); little or no labeled data, none at the start; exploration vs exploitation: lowering the threshold to try "near misses" can discover new interests but risks delivering junk.

Worked example · Lesson 6.6, slide 10

Threshold θ = 30.0. Delivered: 36.5 Rel, 33.4 NonRel, 32.1 Rel. Not delivered: 29.9 ?, 27.3 ?, … No judgments exist below 30.0, so we cannot tell whether 29.9 was relevant.

Empirical utility optimization: on the training data, compute the utility for each candidate threshold and pick the best. Problem: the biased sample gives only an upper bound for the true optimal threshold, so the heuristic fix is to lower it.

Memorize · beta-gamma threshold learning (slide 6.6-12)
$$\theta = \alpha * \theta_{zero} + (1-\alpha) * \theta_{optimal} \qquad \alpha = \beta + (1-\beta) * e^{-N*\gamma}$$

Symbols: $\theta_{optimal}$ = cutoff with maximum utility on training data; $\theta_{zero}$ = lower cutoff where utility drops to zero (the safe limit of exploration); $\alpha$ = how far to move from $\theta_{optimal}$ toward $\theta_{zero}$; $N$ = # training examples; $\beta, \gamma \in [0,1]$; $\beta$ = minimum deviation (an adjustment, e.g. for over-fitting); $\gamma$ = how fast exploration shrinks as $N$ grows.

Why: with few examples ($N$ small, $e^{-N\gamma}\approx1$, $\alpha\approx1$) explore down to $\theta_{zero}$. With many examples ($\alpha\to\beta$) stay closer to $\theta_{optimal}$. "The more examples, the less exploration."

Constructed example (not from the lecture)

$\theta_{zero}=20$, $\theta_{optimal}=30$, $\beta=0.5$. At $N=0$: $\alpha = 0.5+0.5\cdot1 = 1$, so $\theta = 20$ (full exploration). As $N\to\infty$: $\alpha\to0.5$, so $\theta = 0.5\cdot20+0.5\cdot30 = 25$.

Pros: explicitly handles the exploration-exploitation tradeoff ("safe" exploration), works with arbitrary utility (with a lower bound), empirically effective. Cons: purely heuristic; the zero-utility lower bound is often too conservative.

Exam trap

The α, β, γ here are not the Rocchio or PageRank parameters. Also, (10, −1) makes a filter deliver more, and (1, −10) makes it deliver less.

Collaborative filtering (memory-based)

Exam topic 28 · Lessons 6.7, 6.8, 6.9

Idea: to predict whether the active user will like an item, look at similar users and what they thought of it ("who likes X, and is U similar to them?"). User similarity is judged from their preferences on a common set of items. Item content is never used, so CF works for any items (movies, books, products).

Assumptions: users with the same interest have similar preferences, and users with similar preferences share the same interest (e.g., "interest is information retrieval" ⇔ "favor SIGIR papers"). Also, enough preferences must be available; otherwise there is a cold start problem.

The problem (slide 6.7-6): users $u_1,\dots,u_m$, objects $o_1,\dots,o_n$. Unknown function $f: U \times O \to R$ with $X_{ij} = f(u_i, o_j)$. Some values are known (a sparse ratings matrix); predict the rest. It is function approximation, like other learning problems.

Memorize · memory-based prediction (slide 6.7-7)
$$\hat{v}_{aj} = k\sum_{i=1}^{m} w(a,i)\, v_{ij} \qquad \hat{x}_{aj} = \hat{v}_{aj} + n_a \qquad k = 1/\sum_{i=1}^{m} w(a,i)$$

Symbols: $X_{ij}$ = rating of object $o_j$ by user $u_i$; $n_i$ = average rating of all objects by user $u_i$; $V_{ij} = X_{ij} - n_i$ = normalized rating; $u_a$ = the active user; $m$ = number of users; $w(a,i)$ = similarity between $u_a$ and $u_i$; $k$ = normalizer that makes the weights sum to 1; $\hat{v}_{aj}$ = predicted normalized rating; $\hat{x}_{aj}$ = predicted rating of $o_j$ by $u_a$.

Slide note: the bullets use uppercase $X_{ij}, V_{ij}$; the formulas use lowercase $x, v$. Same quantities.

Why normalize? Some users are generous (high ratings for everything), others are critical. Subtracting each user's average makes ratings comparable before averaging them. Why add $n_a$ back? To return to the active user's own rating scale, e.g. to compare predictions with actual ratings in evaluation. Why $k$? So the prediction is a weighted average and stays in the same range as the ratings. Methods differ only in how they choose $w(a,i)$.

Memorize · user similarity (slide 6.7-8)

Pearson correlation coefficient (sum over commonly rated items):

$$w_p(a,i) = \frac{\sum_j (x_{aj}-n_a)(x_{ij}-n_i)}{\sqrt{\sum_j (x_{aj}-n_a)^2 \sum_j (x_{ij}-n_i)^2}}$$

Cosine measure:

$$w_c(a,i) = \frac{\sum_{j=1}^{n} x_{aj}x_{ij}}{\sqrt{\sum_{j=1}^{n} x_{aj}^2 \sum_{j=1}^{n} x_{ij}^2}}$$

Pearson is high when the two users rate the same items above (or below) their own averages. Cosine treats rating vectors like document vectors in the VSM. Here $n$ = number of objects.

Predict active user $u_a$'s rating of $o_5$. Blank = not rated.

1. Deviations on the common items $o_1,o_2,o_3$. $u_a$: $(1,-1,0)$. $u_2$: $(1,-1,0)$. $u_3$: $(2,0,-2)$.

2. Pearson. $w_p(a,2) = \frac{1+1+0}{\sqrt{2\cdot2}} = \frac{2}{2} = 1$. $w_p(a,3) = \frac{2+0+0}{\sqrt{2\cdot8}} = \frac{2}{4} = 0.5$.

Summary (Lesson 6.9). Filtering is "easy" because user expectations are low and any recommendation beats none. It is "hard" because it needs a binary decision now, data are sparse, and cold start is serious. Practical systems are often hybrid (content-based + CF) and use more context.

$n_i$ is a user's average rating, not a count. Remember to add $n_a$ back for the final predicted rating, and divide by the sum of the weights ($k$), not by the number of users.

Part 6 · Word association and topic mining

Paradigmatic vs. syntagmatic relations

Exam topic 29 · Lesson 7.7

These are the two basic, complementary relations between words. They generalize to any units in a sequence, such as phrases.

Memorize

Paradigmatic: "A & B have paradigmatic relation if they can be substituted for each other (i.e., A & B are in the same class)". E.g., "cat" and "dog"; "Monday" and "Tuesday".

Syntagmatic: "A & B have syntagmatic relation if they can be combined with each other (i.e., A & B are related semantically)". E.g., "cat" and "sit"; "car" and "drive".

Test by substitution. "My cat eats fish" → "My dog eats fish" still makes sense, so the relation is paradigmatic. "My sit eats fish" does not make sense, so cat–sit is not paradigmatic. But "the cat sits" combines the two words, so cat–sit is syntagmatic.

Paradigmatic words occur in the same or similar positions (similar context). Syntagmatic words tend to co-occur.

Worked example · Lesson 7.7, slides 6–7

Corpus: "My cat eats fish on Saturday / His cat eats turkey on Tuesday / My dog eats meat on Sunday / His dog eats turkey on Tuesday".

Blank out cat and dog. Both have left context {My, His} and right context {eats}, so cat–dog is paradigmatic. Context(cat) is much more like context(dog) than like context(computer).

Now ask: whenever "eats" occurs, what else occurs? Seeing "eats" helps predict "meat" (syntagmatic), but it does not help predict "text".

Why mine them? They improve NLP tasks (POS tagging, parsing, entity recognition, acronym expansion, grammar learning). In retrieval, they suggest query variations (query expansion). They can build a topic map (words as nodes, associations as edges). And they can compare opinions, e.g. which words are most associated with "battery" in positive vs. negative iPhone 6 reviews.

Exam trap

Don't swap the definitions. Paradigmatic = same class, so the words can be replaced by each other (cat/dog). Syntagmatic = combine in one sentence (car/drive). Replacing a word by a syntagmatically related word usually makes the sentence ungrammatical or meaningless.

Discovering the relations: context similarity, EOWC, BM25 + IDF

Exam topic 30 · Lessons 7.7, 7.8, 7.9

Memorize · general ideas (7.7, slide 8)

Paradigmatic: represent each word by its context → compute context similarity → words with high context similarity are likely paradigmatic.

Syntagmatic: count how often two words occur together in a context (sentence, paragraph) → compare the co-occurrences with the individual occurrences → words with high co-occurrence but relatively low individual occurrence are likely syntagmatic. Put another way: how well does knowing whether B is present predict whether A is present?

"Paradigmatically related words tend to have syntagmatic relation with the same word → joint discovery of the two relations."

Context as a pseudo document (7.8). Collect the words around a word into a bag of words, e.g. Left1("cat") = {"my", "his", "big", "a", "the",…}, Right1("cat") = {"eats", "ate", "is", "has",…}, Window8("cat") = {"my", "his", "big", "eats", "fish",…}. Left1/Right1 find words of the same syntactic class. A wide window finds looser relations. Overall similarity can add up the views:

$$Sim(\text{"Cat"},\text{"Dog"})=Sim(Left1(\text{"cat"}),Left1(\text{"dog"}))+Sim(Right1(\text{"cat"}),Right1(\text{"dog"}))+\dots+Sim(Window8(\text{"cat"}),Window8(\text{"dog"}))$$

Each context becomes a vector in the vector space model: $d1=(x_1,\dots,x_N)$ for "cat" and $d2=(y_1,\dots,y_N)$ for "dog", where N is the vocabulary size.

Memorize · EOWC (7.8, slide 7)
$$Sim(d1,d2)=d1.d2=\sum_{i=1}^{N}x_iy_i,\qquad x_i=c(w_i,d1)/|d1|,\quad y_i=c(w_i,d2)/|d2|$$

Symbols: $c(w_i,d1)$ = count of word $w_i$ in d1; $|d1|$ = total count of words in d1. So $x_i$ is the probability that a randomly picked word from d1 is $w_i$. The dot product is the probability that two randomly picked words from d1 and d2, respectively, are identical.

Worked example (small numbers)

d1 = {eats:2, the:2} (|d1| = 4); d2 = {eats:1, the:3} (|d2| = 4). Then $x$ = (0.5, 0.5) and $y$ = (0.25, 0.75), so Sim = 0.5·0.25 + 0.5·0.75 = 0.125 + 0.375 = 0.5. Most of the score comes from matching "the", which tells us almost nothing. That is problem 2 below.

Two problems with EOWC (7.8, slide 8): (1) it favors matching one frequent term very well over matching more distinct terms; (2) it treats every word equally (overlap on "the" isn't as meaningful as overlap on "eats").

The fixes come from retrieval (7.9). Problem 1 → a sublinear TF transformation, so one frequent word can't dominate. Problem 2 → IDF weighting, so matching a rare word counts more.

Memorize · IDF and the BM25 adaptation (7.9)
$$IDF(W)=\log\left[\frac{M+1}{k}\right]$$

M = total number of docs in the collection; k = number of docs containing W (doc frequency). The maximum is $\log(M+1)$ at k = 1; as k approaches M, IDF gets close to 0.

$$Sim(d1,d2)=\sum_{i=1}^{N}IDF(w_i)\,x_i\,y_i,\qquad x_i=\frac{BM25(w_i,d1)}{\sum_{j=1}^{N}BM25(w_j,d1)}$$ $$BM25(w_i,d1)=\frac{(k+1)\,c(w_i,d1)}{c(w_i,d1)+k\,(1-b+b*|d1|/avdl)},\quad b\in[0,1],\ k\in[0,+\infty)$$

Symbols: b controls length normalization; avdl is the average length of the context documents; $y_i$ is defined the same way. "BM25 + IDF weighting represents the state of the art."

Syntagmatic relations come free as a by-product (7.9, slide 15). Re-weight the context vector of word w by IDF: $(x_1*IDF(w_1),\dots,x_N*IDF(w_N))$. "The highly weighted terms in the context vector of word w are likely syntagmatically related to w." They are frequent near w but not frequent in the whole collection.

Exam-PDF extras: context vectors are also used for word sense disambiguation (compare a mention's context with each sense's typical context), and they relate to word embeddings (word2vec learns an "implicit" vector). Entropy- and mutual-information-based syntagmatic mining is in optional lessons and is not tested.

Exam trap

Watch the letters. Here N is the vocabulary size and M is the number of documents (in IDF). In the topic-model lessons, N = number of documents and M = vocabulary size. Also, the letter k is the doc frequency in IDF but the TF parameter in BM25.

Exam trap

Match each fix to its problem. The sublinear TF fixes "one frequent term dominates". IDF fixes "every word treated equally". Large BM25 k behaves like the raw count; k = 0 behaves like the 0/1 bit vector.

The two basic tasks of topic mining

Exam topic 31 · Lesson 7.14

A topic is the main idea discussed in text data: the theme or subject. It can have different granularities (a sentence, an article, a collection). Applications include: what are Twitter users talking about today? How do current data-mining research topics differ from 5 years ago? What do people like or dislike about the iPhone 6?

Memorize · task definition (7.14, slide 6)

Task 1: Discover k topics. Task 2: Figure out which documents cover which topics (to what extent).

Input: a collection $C=\{d_1,\dots,d_N\}$ and the number of topics k. Output: k topics $\{\theta_1,\dots,\theta_k\}$ and the coverage $\{\pi_{i1},\dots,\pi_{ik}\}$ of each $d_i$, where $\pi_{ij}$ = prob. of $d_i$ covering topic $\theta_j$, and

$$\sum_{j=1}^{k}\pi_{ij}=1$$

Why does the coverage sum to 1? The document can't cover topics outside the k we discover, so its coverage is a distribution over those k topics. If it is all on one topic, the document covers a single topic.

Worked example · Lesson 7.15, slide 3

Doc 1: $\pi_{11}$ = 30% (Sports), $\pi_{12}$ = 12% (Travel), $\pi_{1k}$ = 8% (Science), with the rest on other topics. Doc 2 does not cover Sports: $\pi_{21}=0$.

Once you have coverage per document, you can add it up over any subset of documents, such as those with one time stamp or from one location. That enables temporal trends and comparisons between collections, which is the link to context (topic 50).

Exam trap

The sum-to-1 constraint is over topics j for one document ($\sum_j\pi_{ij}=1$), not over documents. And in these methods k is an input; you must specify it.

Term as topic, and its problems

Exam topic 32 · Lesson 7.15

The first idea is to let each topic be one term, e.g. $\theta_1$ = "Sports", $\theta_2$ = "Travel", $\theta_k$ = "Science".

Task 1 (find k topical terms). Parse C into candidate terms. Score each term so that representative (frequent) terms are favored but terms that are too frequent ("the", "a") are avoided; TF-IDF weighting does this. Domain heuristics also help (title words, hashtags in tweets). Then pick the k highest-scoring terms while minimizing redundancy: of several similar terms, keep only one. The lecturer calls this a greedy "maximal marginal relevance" ranking.

Memorize · coverage (7.15, slide 5)
$$\pi_{ij}=\frac{count(\theta_j,d_i)}{\sum_{L=1}^{k}count(\theta_L,d_i)}$$

Symbols: $count(\theta_j,d_i)$ is how often the term for topic $\theta_j$ occurs in $d_i$. Dividing by the total makes the k coverages sum to 1.

Worked example · Lesson 7.15, slides 5–6

count("sports", $d_i$) = 4, count("travel", $d_i$) = 2, count("science", $d_i$) = 1, so $\pi$ = 4/7, 2/7, 1/7.

Now take the NBA article "Cavaliers vs. Golden State Warriors: NBA playoff finals … basketball game … travel to Cleveland … star …":

Memorize · problems with "term as topic" (7.15, slide 7)

1. Lack of expressive power: can only represent simple/general topics; can't represent complicated topics.
2. Incompleteness in vocabulary coverage: can't capture variations of vocabulary (e.g., related words such as basketball, game).

Topic = word distribution

Exam topic 33 · Lessons 8.1, 8.2

Fix each problem of term-as-topic (8.1, slide 3): use multiple words (expressive power); put weights on words (related words get partial credit); split an ambiguous word across topics (ambiguity). "A probabilistic topic model can do all these!"

Memorize (8.1, slides 4–5)

Each topic $\theta_i$ is a word distribution $p(w|\theta_i)$ over the vocabulary $V=\{w_1,\dots,w_M\}$:

$$\sum_{w\in V}p(w|\theta_i)=1\qquad\sum_{j=1}^{k}\pi_{ij}=1$$

Input: C, k, V. Output: $\{\theta_1,\dots,\theta_k\}$ (each a word distribution) and $\{\pi_{i1},\dots,\pi_{ik}\}$ for each document.

Worked example · Lesson 8.1, slide 4
$P(w|\theta_1)$ "Sports"$P(w|\theta_2)$ "Travel"$P(w|\theta_k)$ "Science"

It is a generalization. If a distribution puts probability 1.0 on one term, it is exactly the term-as-topic model.

The generative-model recipe (8.1, slide 7). Model how the data is generated, $P(\text{Data}|\text{Model},\Lambda)$, where $\Lambda=(\{\theta_1,\dots,\theta_k\},\{\pi_{11},\dots,\pi_{1k}\},\dots,\{\pi_{N1},\dots,\pi_{Nk}\})$. Then estimate

$$\Lambda^*=\arg\max_{\Lambda}p(\text{Data}|\text{Model},\Lambda)$$

and take $\Lambda^*$ as the mined knowledge.

Worked example · Lesson 8.2 (one topic, one document)

The likelihood is $p(d|\theta)=\prod_{i=1}^{M}\theta_i^{c(w_i,d)}$, where $\theta_i=p(w_i|\theta)$. The maximum-likelihood estimate is the normalized count, $\hat\theta_i=c(w_i,d)/|d|$. Example: d = "text mining text the" gives p(text) = 2/4, p(mining) = 1/4, p(the) = 1/4.

On the slide's text-mining paper (Lesson 8.2, slide 6), common words such as "the" (0.031) and "a" (0.018) get probabilities nearly as high as the content words "text" (0.04) and "mining" (0.035). The MLE must explain every word, so common words take a large share. That leads to the background model (topic 34).

Slide note

In 8.2, $\theta_i$ means the probability of the i-th word under one topic $\theta$. In 8.1 it means the i-th topic. In 8.2 the Lagrange step's sum has upper limit "N", but it runs over the M vocabulary words.

Mixture model: probability of a word

Exam topic 34 · Lesson 8.3

Why mix? A single distribution must explain every word, so "the" gets high probability. Instead, give the common words to a second distribution, the background $\theta_B$, so the topic $\theta_d$ only has to explain the content words.

To generate each word: first choose a component (the "switch", like a coin with probabilities $p(\theta_d)$ and $p(\theta_B)$); then sample the word from the chosen distribution.

Memorize (8.3, slide 7)
$$p(w)=p(\theta_d)p(w|\theta_d)+p(\theta_B)p(w|\theta_B),\qquad p(\theta_d)+p(\theta_B)=1$$

General rule: sum over the components; each term is (probability of choosing that component) × (probability of the word from that component). With k topics: $p(w)=p(\theta_1)p(w|\theta_1)+\dots+p(\theta_k)p(w|\theta_k)$.

Symbols: $\theta_d$ is the topic of d; $\theta_B$ is the background topic; $p(\theta_d)$ and $p(\theta_B)$ are the mixing weights (topic choice).

Worked example · Lesson 8.3, slide 5
$$P(\text{"the"})=0.5*0.000001+0.5*0.03=0.0150005$$ $$P(\text{"text"})=0.5*0.04+0.5*0.000006=0.020003$$

(The slide shows only the expressions; the totals are the arithmetic.) "the" is almost entirely explained by $\theta_B$, and "text" by $\theta_d$.

Likelihood of the whole document (8.3, slide 8): it is the one-topic product with a sum inside:

$$p(d|\Lambda)=\prod_{i=1}^{M}[p(\theta_d)p(w_i|\theta_d)+p(\theta_B)p(w_i|\theta_B)]^{c(w_i,d)}$$

Here $\Lambda=(\{p(w|\theta_d)\},\{p(w|\theta_B)\},p(\theta_B),p(\theta_d))$, and $\Lambda^*=\arg\max_\Lambda p(d|\Lambda)$ subject to each distribution summing to 1 and $p(\theta_d)+p(\theta_B)=1$.

A Bayes-rule view (exam PDF). Treat each $\theta_i$ as a hypothesis $H_i$. Then $p(\theta_i)$ is the prior, $p(w|\theta_i)$ is $p(D|H_i)$ for D = the observed word, and the mixture sum is exactly $p(D)$. The posterior $p(\theta_i)p(w|\theta_i)/p(w)$ says which component probably generated w. That is the E-step (topic 36).

Exam trap

Slide-7 question: "What if $p(\theta_d)=1$ or $p(\theta_B)=1$?" The mixture reduces to the single-distribution model, so it covers the one-topic model as a special case. And don't multiply the components together: the components are added, weighted by their selection probabilities.

How the components collaborate and compete; the background model

Exam topic 35 · Lessons 8.4, 8.5

Setup: fix $\theta_B$ and $p(\theta_d)=p(\theta_B)=0.5$, and estimate only $\theta_d$. In-lecture question: "Would the ML estimate demote background words in $\theta_d$?" Yes.

Worked example · Lesson 8.4, slides 5–6

d = "text the"; $\theta_B$: the 0.9, text 0.1.

$$p(d|\Lambda)=[0.5*p(\text{"text"}|\theta_d)+0.5*0.1]\times[0.5*p(\text{"the"}|\theta_d)+0.5*0.9]$$

The two brackets add up to a constant: 0.5·1 + 0.5·1 = 1, because $p(\text{"text"}|\theta_d)+p(\text{"the"}|\theta_d)=1$. "If $x+y$ = constant, then $xy$ reaches maximum when $x=y$." So

$$0.5*p(\text{"text"}|\theta_d)+0.5*0.1=0.5*p(\text{"the"}|\theta_d)+0.5*0.9\ \Rightarrow\ p(\text{"text"}|\theta_d)=0.9,\ p(\text{"the"}|\theta_d)=0.1$$

Behavior 1: if $p(w_1|\theta_B)>p(w_2|\theta_B)$, then $p(w_1|\theta_d)<p(w_2|\theta_d)$.

Worked example · Lesson 8.5, slide 7

d′ = "text the the the … the". Every extra "the" multiplies the likelihood by another $[0.5*p(\text{"the"}|\theta_d)+0.5*0.9]$. Question: is the new $p(\text{"the"}|\theta_d)$ above or below 0.1? Above. "the" now occurs many times, so raising its probability gains more than the small loss on the single "text".

Behavior 2: high-frequency words get higher $p(w|\theta_d)$. Question: what if we increase $p(\theta_B)$? Then the "the" factors are already large, so $\theta_d$ has less incentive to raise "the".

Memorize · summary (8.5, slide 8)

• Every component model attempts to assign high probabilities to highly frequent words in the data (to "collaboratively maximize likelihood").
• Different component models tend to "bet" high probabilities on different words (to avoid "competition" or "waste of probability").
• The probability of choosing each component "regulates" the collaboration/competition.
• Fixing one component to a background LM helps "get rid of background words" in the other component. It is an example of imposing a prior (one model must be exactly the background LM).

Exam trap

The fixed background does not delete stop words from the data. It "explains away" those words, so the free topic $\theta_d$ puts its probability on content words that the background explains poorly (like "text", with $p(\text{"text"}|\theta_B)$ = 0.000006).

The EM algorithm

Exam topic 36 · Lessons 8.6, 8.7, 8.8

The idea. If we knew which words came from $\theta_d$, we would put them into a pseudo document d′ and normalize their counts: $p(w_i|\theta_d)=\frac{c(w_i,d')}{\sum_{w'\in V}c(w',d')}$. We don't know, so we guess with Bayes rule using the current parameters. Then we re-estimate, and repeat.

Memorize (8.7, slide 6)

Hidden variable $z\in\{0,1\}$ for each word occurrence: z = 0 means the word came from topic $\theta_d$; z = 1 means it came from background $\theta_B$.

E-step (Bayes rule: "how likely w is from $\theta_d$"):

$$p^{(n)}(z=0|w)=\frac{p(\theta_d)p^{(n)}(w|\theta_d)}{p(\theta_d)p^{(n)}(w|\theta_d)+p(\theta_B)p(w|\theta_B)}$$

M-step (split the counts by z, then normalize):

$$p^{(n+1)}(w|\theta_d)=\frac{c(w,d)\,p^{(n)}(z=0|w)}{\sum_{w'\in V}c(w',d)\,p^{(n)}(z=0|w')}$$

Symbols: $(n)$ is the iteration; $c(w,d)$ is the count of w in d. In the E-step, the prior is $p(\theta_d)$ and $p(\theta_B)$, and the likelihood is $p(w|\theta)$.

Procedure: initialize $p(w|\theta_d)$ with random values, then iterate the E-step and M-step, and stop when the likelihood doesn't change.

Memorize · summary (8.8, slide 9)

• EM is a general algorithm for computing the ML estimate of mixture models.
• It is hill-climbing, so it can only converge to a local maximum (depending on initial points). Run it from several starting points and keep the best.
• E-step: "augment" the data by predicting values of useful hidden variables. Bayes rule is applied here.
• M-step: exploit the "augmented data" to improve the parameter estimates ("improve" is guaranteed in terms of likelihood).
• "Data augmentation" is probabilistic: split the counts of events probabilistically.

A useful by-product (8.7): the $p(z=0|w)$ column tells you how much of the document is content rather than background.

Exam trap

Bayes rule is in the E-step, not the M-step. EM is guaranteed to converge to a local maximum, not necessarily the global one, so run it from several starting points and keep the best (Lesson 8.8). The lecturer adds one fine point: the guarantee is about the likelihood increasing, and the parameter values themselves need extra conditions to settle. On the exam, the answer is "local maximum". And z = 0 means topic here, which is the reverse of what many people guess.

Part 7 · Clustering, categorization, text-based prediction

Text clustering

Exam topic 37 · Lesson 9.1

Clustering discovers "natural structure" by grouping similar objects together. The objects can be documents, terms, passages, sentences, websites, or even all the articles by one author. The problem is not well defined until we say what "similar" means.

Memorize · the clustering bias (9.1, slide 5)

"Any two objects can be similar, depending on how you look at them!" (Are "car" and "horse" similar? Physically no; as transportation, yes.) "A user must define the perspective (i.e., a 'bias') for assessing similarity!" This bias is also the basis for evaluation.

Examples (slide 6): clustering all documents in a collection; term clustering to define a "concept"/"theme"/"topic"; clustering passages or sentences (e.g., segments about one topic → subtopics); clustering websites; further clustering the clusters to build a hierarchy.

Why (slide 7): get a sense of the overall content (typical documents); link similar objects (remove duplicates); create structure for browsing; induce features (cluster membership) for classification. Applications: clustering search results (clusters ≈ senses of an ambiguous query); understanding major complaints in customer emails.

Exam trap

Clustering is unsupervised: there are no labeled training examples, unlike categorization. A question saying "there is one correct clustering of this data" is false unless the bias (perspective) is fixed.

Hierarchical agglomerative clustering: single, complete, average link

Exam topic 38 · Lesson 9.5

HAC is given a similarity function between two objects. It starts with every object in its own group and repeatedly merges the most similar pair of groups (bottom-up) until a stopping criterion is met: a number of clusters, or a similarity threshold. The result is a binary tree that you can cut at any level.

HAC needs a way to compare two groups using only object-to-object similarity. The variants differ only in that.

K-means

Exam topic 39 · Lesson 9.5

Memorize (9.5, slide 10)

1. Represent each text object as a term vector, with a similarity function between objects.
2. Start with k randomly selected vectors as the centroids of k clusters (the initial tentative clustering).
3. Assign every vector to the cluster whose centroid is the closest.
4. Re-compute each centroid from the vectors newly assigned to it (their average).
5. Repeat until the objective (within-cluster sum of squares) converges, to a local minimum.

Why it is "very similar to clustering with EM for a mixture model": random initialization ↔ random initialization; the assignment step ↔ the E-step; the centroid step ↔ the M-step. The difference: k-means makes a hard assignment (each object goes to exactly one cluster), while the E-step makes a probabilistic allocation that splits counts. So the k-means centroid uses only the points assigned to the cluster, at full weight.

Evaluating clustering

Exam topic 40 · Lesson 9.6

Without a bias, "which clustering is better?" has no answer (shapes vs. sizes). Each kind of evaluation injects the bias from somewhere.

Memorize (9.6, slides 4–5)

Direct: "How close are the system-generated clusters to the ideal clusters (generated by humans)?" Humans build a gold-standard partition of a test set; the system clusters the same set; you quantify the similarity with measures such as purity, normalized mutual information, F measure. The bias is imposed by the human assessors.

Indirect: "How useful are the clustering results for the intended applications?" Build a test set for the application; choose a baseline; add clustering to it to get a "clustering system"; compare the two on the application's own measure. The bias is imposed by the intended application.

Example · exam-topics PDF

Indirect: compare a search interface that clusters the results with a baseline interface without clustering, and measure which helps users finish a retrieval task faster or more easily.

Summary points (slide 6): strong clusters tend to show up no matter which method is used; a method's effectiveness depends on whether it captures the desired clustering bias; and choosing the optimal number of clusters is generally hard because the task is unsupervised. The application may fix k (a results page doesn't want 100 clusters). Otherwise, check whether adding mixture components significantly improves the fit; adding a component can never make the fit worse.

Exam trap

Indirect evaluation never scores the clusters themselves. It measures their contribution to an application, compared with a baseline.

Text categorization and its applications

Exam topic 41 · Lesson 9.7

Memorize (9.7, slide 4)

Given a set of predefined categories (possibly forming a hierarchy) and often a training set of labeled text objects, the task is to classify a text object into one or more of the categories.

Categories vary: internal categories characterize the text itself (topic, sentiment). External categories characterize an entity associated with the text (author attribution; rating a restaurant from its reviews).

Applications: news categorization; literature categorization (MeSH annotations); spam email detection; sentiment of reviews or tweets; email sorting and routing (each helpdesk person is a category); author attribution.

Variants (slide 6): binary (relevant/non-relevant, spam/non-spam, positive/negative); K-category (topics, email folders); hierarchical; joint. "Binary categorization can potentially support all other categorizations": a K-category problem can be solved as K one-vs-rest binary problems, and a hierarchy as flat categorization level by level.

Why categorize (slide 7)?

  • Enrich the text representation (keywords + categories). Categories also let you aggregate, e.g. "70% of reviews are positive".
  • Infer properties of entities linked to the text, such as discovering non-native speakers or predicting a politician's party from a speech.

The exam PDF names these two kinds "annotation" and "text-based prediction". An example of prediction is labeling today's news as positive or negative for the stock market.

Exam trap

In categorization the categories are predefined. In clustering the groups are discovered. "One or more" categories is allowed (multi-label), as in the docs × categories matrix of 9.12.

Training data and methods for categorization

Exam topic 42 · Lessons 9.7, 9.8

Memorize

Training data = a set of text documents, each labeled with the category or categories it should get. The correct categories are already known, because human experts annotated them.

Manual rules (9.8, slide 3) work when categories are well defined and easy to tell apart by surface features, and when there is enough domain knowledge. But they are labor intensive (don't scale), they can't handle uncertainty, and rules may be inconsistent (not robust). "Both problems can be solved/alleviated by using machine learning."

"Automatic" (still needs humans): experts (1) annotate data with category labels, which gives the training data, and (2) provide the features (words are the natural start). Machine learning then learns "soft rules": which features separate the categories, and how to combine them to minimize errors on the training data.

Memorize (9.8, slides 5–6)

Learn a classifier $f: X\rightarrow Y$, with X = all text objects and Y = all categories, such that $f(x)=y\in Y$ is the correct category ("correct" according to the training data).

Generative (learn what the data "looks" like in each category): model $p(X,Y)=p(Y)p(X|Y)$ and get $p(Y|X)$ by Bayes rule. The objective is the likelihood, so it measures training errors only indirectly. E.g., Naïve Bayes.

Discriminative (learn what features separate the categories): model $p(Y|X)$ directly. The objective measures training errors directly. E.g., Logistic Regression, SVM, kNN.

Exam trap

Naïve Bayes is generative, not discriminative. kNN, SVM and logistic regression are discriminative. And "automatic" learning still needs humans for the labels and the features.

How to evaluate categorization

Exam topic 43 · Lessons 9.12, 9.13

Memorize (9.12, slide 3)

Have humans create a test collection where every document is tagged with the desired categories ("ground truth"). Run the system on it. Compare the system's decisions with the human decisions and quantify their similarity: the higher, the better. This is the Cranfield methodology from 1960s information retrieval.

Different mistakes can have different costs depending on the application. "It is okay not to consider such a cost variation for relative comparison of methods": a simplified measure that is biased the same way for every method still ranks the methods correctly.

Look from several perspectives (per document, per category, macro or micro) to see where a method is weak. The measure must reflect the intended use: spam filtering and news categorization need different measures.

Exam trap

The ground truth is the human labels on a test set, not the system's own training data. Many different measures are possible depending on how errors are treated, so there is no single "correct" measure.

(1) Some errors are more serious than others: in spam filtering, missing a legitimate email costs more than letting a spam through. (2) Imbalanced test sets: with 98% of instances in category 1 and 2% in category 2, the baseline "put all instances in category 1" gets 98% accuracy.

Exam trap

The accuracy denominator is kN, all doc–category decisions, not N. The n(−) cells count as correct. Precision divides by what the system said "y" to; recall divides by what the human marked +.

Why F uses the harmonic mean

Exam topic 45 · Lesson 9.12, slide 8

Slide question: "Why not 0.5*P+0.5*R?" The harmonic mean ($F_1=\frac{2PR}{P+R}$) is dominated by the smaller of P and R. It is high only when both are high. The arithmetic mean lets one perfect value hide a terrible one.

Worked example · slide 8 question "What is R if the system says 'y' for all category-doc pairs?"

A document has 1 true category out of 3, and the system says "y" to all 3. Then R = 1 and P = 1/3.

CombineValue
Arithmetic 0.5P + 0.5R(1/3 + 1)/2 ≈ 0.67
$F_1$2·(1/3)·1/(1/3+1) = (2/3)/(4/3) = 0.5

The extreme case P = 0, R = 1 gives arithmetic = 0.5 but $F_1$ = 0. "If we use an arithmetic mean, we'd still have a mean value of at least 0.5!"

Exam trap

The harmonic mean penalizes extreme (unbalanced) values. It does not "reward recall more"; that is the job of β > 1 in $F_\beta$.

Macro vs. micro averaging

Exam topic 46 · Lesson 9.13

Memorize (9.13, slides 2–4)

Macro: compute P, R and F for each category (or for each document) first, then aggregate (average) them. Every category, or every document, counts equally.

Micro: "First pool all decisions, then compute precision and recall", using one contingency table over all doc–category pairs. Every decision counts equally, ignoring document and category boundaries.

Micro averaging is like accuracy: it treats all decisions equally, so large categories dominate. Aggregation choice matters too: the arithmetic mean is dominated by high values, the geometric mean by low values.

Exam trap

Don't reverse them. Micro = pool first, then compute once. Macro = compute per unit, then average. Macro can be over categories or over documents.

Categorization as ranking

Exam topic 47 · Lesson 9.13, slide 5

Results often go to a human for further editing (correcting news categories) or for prioritizing a task (routing email to the right person). A person checks one item at a time. So if the system gives a score for each decision, rank the decisions and evaluate them as a ranked list, as in search.

Example · Lesson 9.13

Discovering spam emails: rank emails for the "spam" category so a person verifies the most likely spam first. Search is the same idea: ranking documents could be framed as binary relevant/non-relevant categorization, but it is framed and evaluated as ranking because that reflects the user's utility. The exam PDF names a ranking measure: Mean Average Precision.

Exam trap

The reason is human consumption one item at a time (prioritization), not that ranking is computationally cheaper. Evaluate with ranking measures such as MAP, not accuracy.

Text-based prediction and the data mining loop

Exam topic 48 · Lessons 9.14, 7.1, 7.2

Humans are subjective "sensors" (7.1): they perceive the world and express it as text. So text can carry signals for almost any real-world variable, such as product sales, stock prices or election outcomes. Some are easy to predict (whether a product will sell well, from its reviews) and some are hard (stock trends).

Memorize · humans in the loop (9.14)

Humans (1) guide the mining and feature generation (text is created for humans, and humans understand it far better than computers); (2) build, adjust and test the predictive model with domain knowledge; (3) take actions based on the predictions; (4) control the sensors to collect more useful data (related to active learning). That feedback is why it is a loop.

Key questions (slide 4): how to generate effective predictors (features) from text (e.g., topics, sentiment)? How to jointly mine text and non-text data? Slide 5 calls text-based prediction "a unified view of text mining and analysis". The main task is to infer values of real-world variables; the subtasks are mining the content (topics) and mining knowledge about the observer (sentiment). Non-text data and context are added on top.

Exam trap

Text-based prediction usually combines text with non-text data. Predicting stock prices from news alone ignores the historical prices, which matter a lot (7.2). Humans are not removed from the loop; they are central to it.

Joint mining of text and non-text data

Exam topic 49 · Lessons 9.14, 9.15

More data means potentially more knowledge, and each kind of data helps analyze the other.

Memorize (9.14, slide 6)

Non-text data help text mining: non-text data provide context for mining text. This is contextual text mining: partition the text by time, location and so on, then compare the topics across partitions.

Text data help non-text data mining: text helps interpret patterns found in non-text data. This is pattern annotation: split the instances into those that match a pattern and those that don't, compare the topics of their associated text, and the difference (easy for humans to read) suggests what the pattern means.

Example · Lessons 7.2, 9.15

Stock prediction: historical prices (non-text) plus news topics (text). And "Are there topics in news data that are correlated with sudden changes in stock prices?" uses the price time series as context for the text.

Exam trap

Don't swap the directions. Context is the help that flows from non-text to text. Interpretation (pattern annotation) is the help that flows from text to non-text.
